# egos-storage

| | |
|---|---|
| **Path on the system** | `/usr/local/sbin/egos-storage` |
| **Generated by** | `EgOS4-amd64.sh` and `EgOS4-arm64.sh`, section 11b (heredoc `STORAGE_EOF`, identical in the two scripts) |
| **Language** | Bash (`set -euo pipefail`), with embedded Python 3 blocks |
| **Run as** | root only (`sudo`); otherwise it exits with "Run with sudo." |
| **Version** | EgOS 4.3.0 |

## What it is for

It manages the EgOS **storage pool**: a mergerfs filesystem mounted on `/srv/egos/pool` that joins the folder
`/srv/egos/local` (on the system disk) and the data disks `/srv/egos/disks/dataN` (one ext4 per disk,
no RAID: if you lose a disk you lose its files, not the pool).

The pool exists **from the first boot**. The stack (Jellyfin, Immich, Samba) always points to `/srv/egos/pool/...`,
so adding or removing a disk never changes a path.

| Situation | Pool branches | Where new files go |
|---|---|---|
| No data disk | `local=RW` | system disk |
| One or more data disks | `data1=RW:data2=RW…:local=NC` | data disks (`NC` = "no create": `local` stays readable/writable but takes no new files) |
| A disk missing at boot | only the disks present + `local` | pool "degraded", Jellyfin held stopped until the disk is back |

> **Note** — With `minfreespace=20G` a branch with less than 20 GB free takes no new files. If every data disk
> is below that threshold (or the disk is smaller than ~20 GB) writes fail with
> EROFS, because `local` is `NC`. This is intended: the system disk no longer fills up.

## Commands

### Interactive (shell)

| Command | Alias (`/etc/profile.d/egos-storage.sh`) | What it does |
|---|---|---|
| `egos-storage add` (default) | `storage-add` | formats a disk and joins it to the pool "hot" |
| `egos-storage status` | `storage-status` | pool and branch status |
| `egos-storage remove` | `storage-remove` | retires a branch (run it with the disk still connected) |
| `egos-storage reattach` / `remount` | `storage-reattach`, `storage-remount` | remounts disks that came back and refreshes the pool |
| `egos-storage drain` | `storage-drain` | moves files from the system disk to the data disks |
| `egos-storage link` | `storage-link` | installs older than 4.2 only: moves the stack data onto the pool |

### Non-interactive (Cockpit page, scripts)

| Command | Output |
|---|---|
| `status --json` | JSON with pool, branches, stack paths, job |
| `disks --json` | JSON of the disks that can be added |
| `add --disk DEV --confirm DEV` | the confirmation must repeat `DEV` exactly |
| `remove --branch dataN --confirm dataN` | the same with the branch name |
| `link --yes [--immich]` | `--immich` also moves the Immich originals |
| `job <command> <options>` | runs the command as the systemd unit `egos-storage-job` (survives a closed browser); log in `/var/log/egos-storage/job.log` |

### Internal (used by the systemd units)

| Command | Called by |
|---|---|
| `_pool` | `egos-pool.service` (ExecStart) |
| `_pool-ready` | `egos-pool.service` (ExecStartPost) |
| `_guard` | `egos-pool-guard.service` |
| `_autoreattach` | `egos-reattach.service`, started by the udev rule |
| `_job` | the transient unit created by `job` |

### Meaningful exit codes

| Code | Meaning |
|---|---|
| 0 | ok / cancelled by the user |
| 1 | generic error, wrong confirmation, lock busy |
| 2 | `add`: disk formatted and mounted but **not** joined to the pool |
| 3 | `reattach`: at least one disk is still missing |

Required commands (checked at start): `lsblk parted mkfs.ext4 blkid findmnt mountpoint mergerfs udevadm setfattr chattr rsync dd cmp timeout wipefs tr flock findfs`.

## Functions

### fstab handling

Every rewrite goes through a temporary file: NUL/control bytes are dropped and the result is checked
before replacing the real fstab (an interrupted write can leave NUL bytes and an unmounted disk).

#### `fstab_commit <candidate_file>`
Validates and installs a candidate fstab.

1. `sync` of the temporary file.
2. `findmnt --verify --tab-file`: counts **only parse errors** (an unplugged `nofail` disk is an "error" for
   `--verify` but a legitimate state here).
3. Checks that the `/` line still exists.
4. If all is well: backup copy in `/etc/fstab.egos-prev`, atomic `mv`, `sync`.
   If it fails: prints the output, deletes the candidate, returns 1 and **does not touch** `/etc/fstab`.

#### `fstab_del <mountpoint>`
Removes the (uncommented) lines whose field 2 is `<mountpoint>`, stripping NULs; then `fstab_commit`.

#### `fstab_add <line>`
Appends a complete line at the end (after stripping NULs); then `fstab_commit`.

### Concurrency

#### `storage_lock <seconds>`
Opens `/run/egos/storage.lock` on descriptor 9 and takes a `flock`, waiting at most `<seconds>` (0 = fail
at once). It keeps the Cockpit job, a shell command and the udev reattach from overlapping (e.g. `add` formats a
disk labelled `egos-dataN` and udev "sees" a pool disk appear).
Taken with 0 seconds by `add`, `link`, `remove`, `reattach`, `remount`, `drain`; with 900 seconds by `_autoreattach`.

### MOTD warning

#### `motd_update <missing_disks>`
Writes (or deletes, if the argument is empty) a block at the top of `/etc/motd` delimited by
`*** EgOS STORAGE WARNING` … `*** end of EgOS storage warning ***`. The block lists the missing disks and, if
`HELD` exists, adds "Jellyfin is stopped until it is back". The rest of the file is preserved; the file is replaced
only if the content changes.

### The pool

> Golden rule (comment in the code): **never** unmount or restart the pool under a running stack. The containers
> would keep their bind mounts on the old, dead FUSE mount and see empty folders. Every change is applied
> hot through the branches extended attribute.

#### `pool_mounted`
True if `/srv/egos/pool` is mounted (`findmnt`).

#### `configured_disks`
Lists the `/srv/egos/disks/data*` mount points present in fstab, sorted `data1, data2, …` (`sort -V`).

#### `missing_disks`
Among the configured disks, prints those that are **not** mounted.

#### `branch_list`
Builds the branch string for mergerfs: the mounted data disks first (`=RW`), `local` last.
`local` is `=RW` if no data disk is configured, `=NC` otherwise.

#### `update_state`
Updates the state in `/run/egos`: if disks are missing it writes the list to `pool-degraded` and removes the `pool-ok`
gate; otherwise it deletes `pool-degraded` and creates `pool-ok`. Finally it calls `motd_update`.

#### `pool_start`
`systemctl start egos-pool.service` and checks that the pool is mounted. The mergerfs daemon must live in the
service's cgroup, not the caller's: started from the Cockpit job it would be killed when the job ends.

#### `pool_sync`
**Hot** branch update. If the pool is not mounted, it starts it (`pool_start`) and calls `update_state`.
Otherwise it writes `branch_list` into the `user.mergerfs.branches` attribute of the control file
`/srv/egos/pool/.mergerfs` (`srcmounts` is read-only in Debian 13's mergerfs), then `update_state`.
Returns 1 if the attribute cannot be written.

#### `mfs_branches <value>`
Writes the branches attribute directly; used by `do_remove` with `-/path` to detach a single branch.

#### `guard_dir <dir>` / `unguard_dir <dir>`
If `<dir>` is **not** a mount point, makes it immutable (`chattr +i`) / unlocks it (`chattr -i`). An empty mount
point must never receive files: mounting over it works, writing into it does not.

### The `egos-pool` service

#### `do_pool_run` (command `_pool`)
ExecStart of `egos-pool.service`.

1. Exits if the pool is already mounted.
2. **Migration**: installs older than 4.2 mounted the pool from fstab; if it finds that line it removes it
   (`fstab_del`) and runs `daemon-reload`.
3. Makes the pool mount point and those of the configured disks immutable (`guard_dir`).
4. Waits up to `DISK_WAIT` seconds (60) for missing disks to appear (slow USB).
5. `update_state`; if some disk is still missing it prints `DEGRADED: …`.
6. `exec mergerfs -f -o $MFS_OPTS <branches> /srv/egos/pool` (in the foreground: the process is the service).

#### `do_pool_ready` (command `_pool-ready`)
ExecStartPost: waits up to `DISK_WAIT + 30` seconds for the pool to show as mounted. This way the unit is "started"
only once the pool is really there (docker and smbd start after it).

### Protecting Jellyfin

Docker restarts its own containers at boot, before any EgOS unit can step in. That is why the
compose file mounts the gate `/run/egos/pool-ok` inside Jellyfin with `create_host_path: false`: if the gate does not
exist Docker **refuses** to start Jellyfin. This way the library scan never sees missing titles (it would delete them
together with their metadata and watch history).

#### `jellyfin_release`
If `HELD` exists, runs `docker start jellyfin`; if that succeeds, deletes `HELD`.

#### `do_guard` (command `_guard`)
Run by `egos-pool-guard.service` after docker and the deployment.

- Degraded pool: waits up to 60 s for the `jellyfin` container to exist, creates `HELD`; if Jellyfin is running
  (stack installed before the gate existed) it stops it with `docker stop`, otherwise it records that the gate keeps it off.
  Updates the MOTD.

- Complete pool: `jellyfin_release`.

### Reattach

#### `do_reattach` (commands `reattach`, `remount`)
For each missing disk it tries a plain `mount` (fails at once if the disk is absent, instead of waiting for the
mount unit's timeout). Then `pool_sync`. If something is still missing it prints the disks and exits with code **3**
("Check cable and power… If the disk is gone for good: storage-remove"); otherwise `jellyfin_release`.

#### `do_autoreattach` (command `_autoreattach`)
Started by the udev rule `90-egos-reattach.rules` when a partition labelled `egos-data*` appears.

1. Does nothing if `egos-pool.service` is not active (at boot the service itself takes care of it).
2. `udevadm settle` (several disks plugged in together = a single pass), then `storage_lock 900`.
3. Looks, among the missing disks, for those whose fstab source (`UUID=…`) can now be found (`findfs`). It also
   considers the "stale" state: pool marked degraded but no disk missing any more.
4. If there is something to do it runs `do_reattach`, writing the output to `job.log` (visible in Cockpit as "Last
   operation") and to the journal.

### Link (legacy installs)

#### `env_get <key>`
Reads the value of `<key>` from the stack's `.env` file (`$ENVF`), last occurrence.

#### `move_tree <env_key> <destination>`
Moves the folder named by a `.env` key onto the pool, with verification:

1. skips if the key is missing, already equal to the destination, or if the folder does not exist;
2. checks the free space (size + 1 GiB margin);
3. `rsync -aHAX --numeric-ids`;
4. **check 1**: a second `rsync` in dry-run must have nothing to transfer;
5. **check 2**: same number of files at source and destination;
6. renames the original to `<folder>.pre-pool` and updates `.env`.
On any error the source stays intact and `.env` does not change.

#### `do_link` (command `link`)
For installs older than 4.2 (the stack was not on the pool). Finds the user from `/var/lib/setup-data.json`,
asks (or takes from `--yes`/`--immich`) whether to move the Immich originals too, saves `.env`
(`.env.bak.<date>`), stops the stack (`docker compose down`), calls `move_tree` for
`JELLYFIN_MEDIA_LOCATION` → `/srv/egos/pool/media` and, if requested, `UPLOAD_LOCATION` → `/srv/egos/pool/immich/upload`,
fixes the permissions, updates the `path` of the Samba share `[media]`, restarts smbd/wsdd2 and the stack.
Immich's Postgres database **always stays on the system disk** (a DB on a USB disk is easily corrupted).
The `.pre-pool` folders have to be deleted by hand.

### Status

#### `do_status` (command `status`)
Prints: mounted branches (`findmnt`), each `dataN` with source/size/space or `NOT MOUNTED`, usage of
`/srv/egos/local`; then the pool (`df`), the current branch list read from the xattr, any `DEGRADED` state and
"Jellyfin is stopped…".

#### `do_status_json` (command `status --json`)
Python block that produces the JSON read by the Cockpit page:

| Key | Contents |
|---|---|
| `pool` | `path`, `mounted`, `size/avail/used`, `service` (state of egos-pool), `missing[]`, `degraded` |
| `branches[]` | for each `dataN`: `name`, `path`, `in_fstab`, `fstab_source`, `mounted`, `source`, `label`, space, `in_pool`; if not mounted, `stray` = files ended up on the system disk |
| `system_disk` | system disk (e.g. `/dev/nvme0n1`) |
| `local` | `path`, `in_pool`, `mode` (`RW`/`NC`), `has_files` (excluding the `.immich` markers), `system_free` |
| `jellyfin_held` | true if `HELD` exists |
| `stack` | `.env` path and values of `JELLYFIN_MEDIA_LOCATION`, `UPLOAD_LOCATION`, `DB_DATA_LOCATION` |
| `samba_media_path` | `path` of the `[media]` section of `smb.conf` |
| `job` | `unit`, `state`, `running`, `log`, `has_log` |

### Disk integrity test

#### `verify_disk <mountpoint>`
A fake-capacity device accepts writes, says "ok" and returns different data: `mkfs` succeeds, the ext4 gets
corrupted later. The test:

1. generates 128 MiB of random data in `/var/tmp`;
2. writes it to the disk with `conv=fdatasync`, within 180 s (otherwise: disk unusable at this speed);
3. drops the cache (`drop_caches`) and compares byte by byte (`cmp`);
4. checks that the kernel logged no new `EXT4-fs error` in `dmesg`;
5. prints the approximate write speed.
Returns 1 at the first failure.

### Removal

#### `do_remove` (command `remove`)
Retires a branch **without formatting**. Run it with the disk still connected (it also works if it is already unplugged, but
then any writes not yet on the disk are lost).

1. Lists the branches, picks the one from `--branch` or from numeric input.
2. Works out whether the disk is connected (`ATTACHED`); warns if it is the **last** data disk (new files go back to
   the system disk).
3. Asks to type the branch name exactly (`dataN`).
4. Detaches the branch hot (`mfs_branches -<path>`).
5. `sync`.
6. Unmounts: with the disk connected the unmount must succeed **cleanly**; if something keeps the branch open it shows
   `lsof`, puts the branch back in the pool and stops ("Do NOT unplug the disk"). With the disk absent it uses `umount -f`/`-l`.
7. Removes the line from fstab; if the empty folder remains, unlocks and removes it; if it is not empty it warns (files
   ended up on the system disk).
8. `pool_sync`; if no disk is missing any more, `jellyfin_release`.
9. Removes the device from the kernel (`/sys/block/<disk>/device/delete`) and prints
   **"YOU CAN NOW SAFELY UNPLUG THE DISK"**.

### Adding

#### `sys_disk`
The disk holding `/` (e.g. `/dev/nvme0n1`), found with `findmnt` + `lsblk PKNAME`.

#### `candidates <system_disk>`
Python over `lsblk -J`: lists the whole disks that can be added, as TSV (`name size bus model mountpoint`).
Excludes the system disk, `zram`, `loop`, `fd` (floppy controllers on x86 boards and VMs), eMMC boot/RPMB areas.

#### `do_disks_json` (command `disks --json`)
Converts the output of `candidates` into JSON (`name, size, tran, model, mountpoints`). Stops if the system disk
cannot be determined.

#### `do_add` (command `add`, default)
1. Determines the system disk (if it cannot, it stops: it never risks formatting it).
2. Lists the candidates; picks from `--disk` or from numeric input.
3. Shows the contents; stops if there are mounted partitions.
4. Asks to type the device name exactly.
5. Picks the first free `dataN`: it **never reuses** the name of a configured but temporarily absent disk
   (its fstab line would be overwritten).
6. `wipefs -a`, GPT table, one partition at 100 %, `mkfs.ext4 -L egos-dataN -m 1`.
7. Creates the mount point (immutable), adds to fstab
   `UUID=… /srv/egos/disks/dataN ext4 defaults,nofail,noatime,x-systemd.device-timeout=60 0 2`, mounts.
8. `verify_disk`: if it fails it unmounts, removes the fstab line, removes the folder and stops ("the disk does NOT join the pool").
9. Gives ownership to the user created at setup (Samba and the services can write).
10. `pool_sync` (hot attach, no service restart). If it fails it exits with code **2** and suggests
    `storage-reattach`.

### Drain

#### `do_drain` (command `drain`)
Moves files from `/srv/egos/local` to the data disks keeping the same relative path: no service notices.

1. Requires at least one mounted data disk and the pool mounted.
2. **Greedy plan** (Python): files from largest to smallest, each onto the disk with the most space, keeping 20 GiB
   in reserve per disk (like `minfreespace`). Skips files changed in the last 10 minutes and the `.immich` markers.
   Prints the plan and the files that do not fit.
3. For each disk: `rsync -aHAX --from0 --files-from=… --remove-source-files` (rsync writes to a temporary name and
   renames at the end: nobody ever reads a half-written file).
4. The folder tree and the `.immich` markers always stay on the system disk: if every disk is removed the
   stack finds its folders again (Immich does not start without the markers).
5. Reports how many files are left; exits with 1 if some move failed (run it again to retry).

### Jobs

#### `do_start_job <command…>` (command `job`)
Accepts only `add|remove|link|remount|reattach|drain`. Refuses if `egos-storage-job` is already active, then
`systemd-run --unit=egos-storage-job --collect --setenv=HOME=/root … egos-storage _job <command…>`.

#### `do_run_job <command…>` (command `_job`)
Inside the unit: writes the header `== <date> egos-storage …` to `job.log`, runs the command with stdin from
`/dev/null` appending everything to the log, closes with `== END rc=<code> <date>` and returns the code.

### Final dispatcher
Takes `storage_lock 0` for the commands that change something, then routes `CMD` to the matching function; an
unknown command prints the usage and exits with 1.
