# wizardall2.sh

| | |
|---|---|
| **Path** | `/usr/local/share/stack/wizardall2.sh` → copied to `~/app/repos/wizardall2.sh` |
| **Generated by** | section 11 of the EgOS4 scripts |
| **Started by** | `dirtree.sh` (`exec`) |
| **Philosophy** | "zero-errors mentality": `set -e`, every failing `curl -f` stops everything |

## Purpose

Starts the Docker stack and completes the initial configuration of Immich and Jellyfin through their APIs, so the user
never has to open their setup wizards.

## Steps

| # | Message | Action |
|---|---|---|
| 0 | — | `cd` into the script's folder (the `curl -d @file.json` calls use relative paths) |
| 1 | `Starting compose` | `docker compose -f docker-compose.yml up -d` |
| 2 | `Waiting for Jellyfin…` | loops until `GET :8096/health` = 200 |
| 3 | `Waiting for Immich…` | loops until `GET :2283/api/server/ping` contains `pong` |
| 4 | `IMMICH USERSET` | `POST :2283/api/auth/admin-sign-up` with `immichset.json`. If it fails (admin already created in an earlier attempt) it carries on |
| 5 | — | reads `GET /System/Info/Public` (retried until it answers); if it holds `"StartupWizardCompleted":true` the whole Jellyfin Startup block (steps 6–11) is skipped: "already completed in a previous run" |
| 6 | — | waits until `GET :8096/Startup/Configuration` = 200 |
| 7 | `JELL SRVSET` | `POST /Startup/Configuration` with `jellsrv.json` (server name `EgoFin`, interface and metadata in Italian) |
| 8 | — | waits for `GET /Startup/User` = 200 (the GET is mandatory before the POST) |
| 9 | `JELL USERSET` | `POST /Startup/User` with `jelluser.json` |
| 10 | `JELL ACCESSET` | `POST /Startup/RemoteAccess` with `jellremot.json` (remote access yes, UPnP no) |
| 11 | `--- Complete ---` | `POST /Startup/Complete` |
| 12 | `--- Verify ---` | prints `GET /System/Info/Public`, then `ALL OK` |

## Functions

None.

## Re-runs (since 4.2.2)

Once Jellyfin's wizard is complete, the `/Startup/*` APIs answer 401. Before 4.2.2 the wait in step 6 then never ended
when `docker-compose-startup.service` retried at boot; now step 5 detects the completed wizard and skips it, so the
script can be run again safely.
